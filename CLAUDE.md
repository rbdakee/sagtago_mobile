# SaqtaGo — Mobile App (клиент)

> Этот файл — постоянный контекст для Claude Code. Держим его коротким и точным.
> Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) · [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md) · бизнес-логика [docs/BP.md](docs/BP.md) · дизайн-спека [docs/DESIGN.md](docs/DESIGN.md).

## Что это
SaqtaGo — приложение спасения еды для Казахстана (модель Too Good To Go). Заведения
отдают свежие излишки «боксами-сюрпризами» со скидкой до 70%; покупатель бронирует,
платит онлайн сразу и забирает самовывозом по коду/QR.

**Этот репозиторий = ТОЛЬКО клиентское (покупательское) мобильное приложение.**
Бэкенд, админ-веб и суперадмин — отдельные проекты. Отсюда их не трогаем.
**Работаем только в `mobile_app/`.**

## Стек
- Expo (managed) + React Native + TypeScript
- Навигация: **expo-router** (file-based)
- Стили: **типизированный theme-object + StyleSheet + `useTheme()`** (токены — единственный источник правды)
- Server-state: **TanStack Query** · Local/UI/auth-state: **Zustand**
- Формы: react-hook-form + zod
- i18n: **i18next + expo-localization** (RU дефолт, KK обязателен)
- Секреты: expo-secure-store · Пуши: expo-notifications
- Сборка: **EAS dev build** (Expo Go не используем — нужны нативные модули и blur)

## Железные правила
1. **Токены — единственный источник правды.** Никаких хардкод-HEX/размеров в компонентах.
   Цвета, отступы, радиусы, тени, типографика — только из theme-объекта
   (порт `docs/mobile_design/sg/project/tokens.css`).
2. **Две темы:** `graphite` (светлая, дефолт) + `graphite-dark`. Каждый компонент обязан
   корректно выглядеть в обеих. Dark = следуем системе + ручной оверрайд в Профиле.
3. **Дизайн делаем ровно как в хендоффе** — `docs/mobile_design/sg/project/`
   (Prototype.html, components.css, UI Kit.html, скриншоты). Pixel-perfect.
   4 таба: Главная · Заказы · Избранное · Профиль. Liquid Glass — только на навигации,
   таб-баре, bottom-sheet, модалках, плавающих кнопках.
4. **Никаких хардкод-строк в UI.** Весь текст — через i18n (RU + KK). Строки KK длиннее —
   контейнеры гибкие, ширину по тексту не фиксируем.
5. **Каждый экран с данными = 4 состояния:** Content / Loading (скелетон) / Empty / Error (ретрай).
6. Форматы: деньги `1 030 ₸` (пробел-разделитель), окно выдачи `20:00–21:30`.
   Тач-таргеты ≥ 44×44. База отступов 8pt (4/8/12/16/24/32).

## Бизнес-правила, влияющие на UI (см. docs/BP.md §0)
- **R1** оплата сразу при брони, резерва без оплаты нет.
- **R2** не пришёл в окно → деньги заведению, **возврата нет**.
- **R3** **отмены брони покупателем нет** (нет кнопки «отменить»).
- **R4** возврат только по жалобе через суперадмина; **фото обязательно**.
- **R6** только самовывоз (нет адреса доставки), выдача по коду/QR.
- Сервисный сбор **3%** показываем в чеке прозрачно, отдельной строкой.

## Статусы (для бейджей и логики)
- Заказ: `created → paid → picked_up | expired | refunded | payment_failed`
- Бокс: `published | sold_out | closed`
- Семантика цветов бейджей — DESIGN.md §4.1 (success/info/warning/danger/muted).

## Данные / API
Бэкенд — отдельный проект, **рабочего API пока нет**. Поэтому:
- Доменные типы и zod-схемы пишем сейчас (из BP.md — они не зависят от транспорта).
- Экраны строим на статичных плейсхолдерах (как и сам прототип).
- Доступ к данным — за **интерфейсами репозиториев**; реальная реализация (API-клиент,
  Query-хуки) подключается, когда бэкенд отдаст контракт. Swap — в одной точке.
- Платёж: бэкенд создаёт сессию Freedom Pay → app открывает страницу провайдера;
  подтверждение приходит на бэкенд вебхуком; клиент дожидается статуса (refetch/пуш). MVP — stub.
