## 2. Бренд и визуальный язык

### 2.1 Анти-требования (важно — чего НЕ делаем)

Заказчик явно просит уйти от «дефолтного облика Claude Design»:
- ❌ **Никакого тёпло-кремового / полу-оранжевого фона** (типичный беж `#F5F1EC`/`#EFE8DE`). Фон — чистый, прохладный.
- ❌ **Не использовать дефолтный шрифт** Claude-генераций (Inter / системный ui-sans как «лицо» бренда). Inter допустим только как технический фолбэк, но не как бренд-шрифт.
- ❌ Без «стокового» AI-вида: избыточные градиенты-сетки, glassmorphism ради него самого, фиолетово-синие неоновые градиенты.
- ✅ Цель — узнаваемый, «вкусный», локальный, доверительный вид. Бренд про **свежесть, спасение еды и честную сделку**.

### 2.2 Принципы

1. **Доверие важнее вау.** Покупатель боится просрочки → дизайн подчёркивает свежесть, рейтинг, гарантию возврата.
2. **Скорость покупки.** Путь карта → бокс → оплата → код должен быть в 3–4 тапа. Минимум экранов.
3. **Выгода на виду.** Всегда видно: цена, зачёркнутая ценность, % скидки.
4. **Рутина в 1 тап** (для заведения): «повторить вчерашний бокс» — главный паттерн.
5. **Контентом правит фото еды.** Карточки крупные, аппетитные.

### 2.3 Цвет — рекомендация + песочница

> Цвет финализируем итеративно («поиграться с цветами»). Ниже **рекомендованное направление A** и два альтернативных — собрать все три как варианты темы, чтобы переключать.

**Направление A — «Fresh Market» (рекомендую):** глубокий вечнозелёный + сочный лаймовый акцент на прохладно-белом фоне. Свежо, съедобно, не похоже на Claude.

| Токен | HEX | Применение |
|---|---|---|
| `--bg` | `#FBFCFA` | основной фон (прохладно-белый, НЕ кремовый) |
| `--surface` | `#FFFFFF` | карточки, листы |
| `--surface-2` | `#F1F4F0` | вторичные блоки, разделители-зоны |
| `--primary` | `#14532D` | вечнозелёный — навбар-акценты, заголовки, иконки |
| `--primary-press` | `#0E3D22` | нажатое состояние primary |
| `--accent` | `#B9F227` | лайм — главные CTA, бейдж скидки, активные состояния |
| `--accent-ink` | `#102A12` | текст на лаймовом акценте (тёмный, контраст) |
| `--text` | `#10231A` | основной текст |
| `--text-muted` | `#5B6B61` | вторичный текст |
| `--border` | `#E2E8E2` | границы, разделители |
| `--success` | `#1F9D55` | успех/выдано |
| `--warning` | `#E0A100` | окно скоро закроется |
| `--danger` | `#D23B3B` | ошибка, жалоба, деборд |
| `--info` | `#2D6BB5` | нейтральные уведомления |

**Направление B — «Midnight Saver»:** чернильный primary + электрик-мятный акцент, светло-серый фон. Премиальнее, строже.
`--bg #F7F8F8`, `--primary #15211C`, `--accent #00E0A4`, `--accent-ink #062019`, `--text #0E1714`.

**Направление C — «Berry Harvest»:** глубокий сливовый + тёплый коралл, фон холодный кремово-белый (но НЕ оранжевый).
`--bg #FAF9FB`, `--primary #3D1E4F`, `--accent #FF6B5E`, `--accent-ink #2A0E18`, `--text #1C1320`.

Правила цвета (для всех направлений):
- Акцент — только для действия/выгоды (CTA, скидка), не заливать им большие площади.
- Контраст текст/фон ≥ **4.5:1** (WCAG AA). Проверить текст на акценте отдельно.
- Семантические цвета (success/warning/danger) держать одинаковыми между темами для узнаваемости статусов.

### 2.4 Типографика (кириллица обязательна!)

> Все шрифты ниже имеют **полную кириллицу** (важно для RU/KK) и доступны бесплатно (Google Fonts). Это сознательно НЕ дефолтные Inter/системные.

**Рекомендованная пара A:**
- **Дисплей/заголовки:** `Unbounded` (геометрический, характерный, полная кириллица) — H1–H2, крупные цифры скидок, бренд-моменты. Использовать дозированно.
- **Текст/UI:** `Onest` (нейтральный современный грот, отличная кириллица) — body, кнопки, поля, таблицы.

**Альтернативные пары** (собрать как переключаемые стили):
- B: `Geologica` (дисплей) + `Golos Text` (UI) — оба кириллические, Golos «русско-первый».
- C: `Manrope` (дисплей, потяжелее) + `Manrope` (UI) — одно семейство, спокойнее.

Не использовать Inter как бренд-шрифт; допустим лишь системный фолбэк в CSS-стеке.

**Типошкала (мобайл, базовый):**

| Стиль | Размер/интерлиньяж | Начертание | Применение |
|---|---|---|---|
| Display | 32 / 38 | Unbounded SemiBold | большая цифра скидки, экран успеха |
| H1 | 24 / 30 | Unbounded Medium | заголовок экрана |
| H2 | 20 / 26 | Onest SemiBold | секции |
| Body-L | 17 / 24 | Onest Medium | цена, важный текст |
| Body | 15 / 22 | Onest Regular | основной |
| Caption | 13 / 18 | Onest Regular | подписи, мета |
| Mono/Code | 28 / 32 | Onest SemiBold, tabular | **код выдачи** (крупно, разрядка) |

Веб (суперадмин/админ): та же иерархия, +1 уровень плотности для таблиц (Body 14, Caption 12).

### 2.5 Сетка, отступы, форма

- **Базовая единица — 8pt.** Отступы кратны 4/8 (4, 8, 12, 16, 24, 32).
- Поля экрана мобайл: **16** по бокам.
- **Скругления:** карточки `16`, кнопки `12`, поля ввода `12`, чипы/бейджи `999` (пилюля), модалки/листы `24` (верхние углы).
- **Тени:** мягкие, низкие. `card`: 0 2 8 rgba(16,35,26,.06). Избегать тяжёлых теней — опора на границы `--border`.
- **Тач-таргеты ≥ 44×44.**

### 2.6 Иконки, иллюстрации, фото

- Иконки: один набор, line-стиль, толщина 1.5–2px (напр. Lucide / Phosphor). Единый размер 24.
- Фото еды — главный визуал карточек, соотношение **4:3**, скругление 16, лёгкий градиент снизу для читаемости бейджей.
- Иллюстрации пустых состояний — простые, в фирменных цветах, без стокового AI-вида. Тема: «спасённая еда», «коробка-сюрприз».
- Лого/нейминг — TBD (см. [PLAN.md](PLAN.md)); в макетах временный леттеринг-плейсхолдер на бренд-шрифте.

## 3. Компоненты (UI-kit — собрать как Figma-библиотеку)

Собрать переиспользуемые компоненты с вариантами и состояниями (default / hover(web) / pressed / disabled / loading / error / focus):

**Базовые**
- Кнопки: `primary` (акцент), `secondary` (контур), `ghost`, `danger`; размеры L/M/S; с иконкой/без; full-width.
- Поля ввода: текст, телефон (с кодом +7), число, селект, textarea; со статусами валидации и подсказкой/ошибкой.
- **OTP-input** (4–6 ячеек) с таймером ресенда.
- Чипы-фильтры (одиночный/множественный выбор).
- Бейджи статусов (см. §4.1) — пилюли с семантическим цветом.
- Тег скидки (крупный, на акценте: «−70%»).
- Тосты/снэкбары (success/error/info), модалки (подтверждение/инфо), нижние шиты (bottom sheet).
- Загрузчик фото (с превью, прогрессом, удалением).
- Рейтинг-звёзды (показ + ввод).
- Empty / Loading (скелетоны) / Error блоки.

**Доменные**
- **Карточка бокса** (главный компонент): фото, лого/имя заведения, расстояние, категория-«сюрприз», цена + зачёркнутая ценность + тег скидки, окно выдачи, остаток («осталось 3»), рейтинг. Состояния: доступен / `sold_out` / закрывается скоро.
- **Маркер на карте**: пин с мини-ценой/кол-вом; кластер.
- **Код выдачи / QR**: крупный код + QR, кнопка «показать ярче».
- **Строка заказа** (лента заведения / история): время окна, имя/код, кол-во, статус.
- **Стат-карточка** (число + подпись + дельта) — для статистики/дашборда.
- **Таблица** (веб, суперадмин): сортировка, фильтр, пагинация, действия в строке.
- **Степпер количества** (− N +) в пределах остатка.

### 4.2 Обязательные состояния каждого экрана со списком/данными

Для **каждого** экрана с данными нарисовать: **Loading (скелетон)**, **Empty (пустое)**, **Error (с ретраем)**, и Content. Это не опционально — это часть хендоффа.

### 4.3 Прочее
- Денежные суммы — формат `1 030 ₸` (пробел-разделитель, символ тенге).
- Время окна выдачи — `20:00–21:30`.
- Тосты для быстрых результатов; модалки — только для необратимых действий (возврат, деборд).
- Локализация RU/KK: тексты могут быть длиннее — закладывать перенос, не фиксировать ширину кнопок по тексту.

## 6. Постраничные спецификации

Формат: **Назначение → Ключевые элементы → Состояния → Действия/переходы**.

### A. Клиентское приложение

**C-01 Splash.** Лого по центру на `--bg`. → авто-переход: авторизован → C-06, иначе → C-02.

**C-02 Онбординг.** 1–2 слайда ценности («Любимые кафе со скидкой до 70%», «Спасаем еду, не выбрасываем»). Кнопка «Начать» → C-03; «Пропустить».

**C-03 Ввод телефона.** Поле телефона с маской `+7 ___ ___ __ __`, согласие с офертой/политикой (ссылки), кнопка «Получить код». Состояния: пустое/невалидный номер/loading. → C-04.

**C-04 Ввод OTP.** OTP-input (4–6 ячеек), подпись «Код отправлен в WhatsApp на +7…», таймер ресенда + «Отправить по SMS». Ошибка «неверный код», лимит попыток. → C-05 (или сразу C-06).

**C-05 Разрешения.** Два запроса: геолокация (зачем — «показать боксы рядом»), пуш («бокс рядом, напоминания»). Кнопки «Разрешить»/«Позже». → C-06.

**C-06 Главная (карта + список).** Верх: поиск/город, иконка фильтра (→C-07). Переключатель **Карта/Список**. На карте — маркеры боксов (цена/кол-во), кластеры, «моё местоположение». Список — карточки боксов (компонент). Pull-to-refresh. **Состояния:** Loading (скелетон карточек), **Empty** («рядом пока нет боксов» + CTA включить пуш), Error. Тап по карточке/маркеру → C-08.

**C-07 Фильтры (bottom sheet).** Тип заведения (чипы), окно выдачи (диапазон времени), цена (слайдер/чипы). «Применить» (показывает кол-во результатов), «Сбросить».

**C-08 Карточка бокса.** Фото (4:3), имя+лого заведения, рейтинг, адрес+расстояние, кнопка «Открыть в 2GIS». Блок выгоды: **цена крупно**, зачёркнутая ценность, тег «−70%». Категория-«сюрприз» (что примерно внутри). Окно выдачи, «осталось N». Блок доверия: «гарантия свежести / возврат при проблеме». Закреплённый низ: CTA **«Забронировать»**. Состояния: доступен / `sold_out` (CTA выключен) / закрывается скоро (warning). → C-09.

**C-09 Бронь: количество + итог.** Степпер количества (≤ остаток). Сводка суммы: `цена × N`, **строка «Сервисный сбор 3%» раскрыта явно**, итог к оплате крупно. Напоминание правил: «забрать в окне 20:00–21:30», «отмена невозможна» (R3), «не заберёте — деньги не возвращаются» (R2) — коротко и честно. CTA «Перейти к оплате» → C-10.

**C-10 Оплата.** Методы: карта, **Kaspi**, Apple/Google Pay. Экран/шит провайдера. Состояния: processing, success → C-11, **fail** («оплата не прошла, попробуйте снова», бокс не забронирован — BP-05).

**C-11 Успех брони.** Крупная галочка/иллюстрация, «Бронь подтверждена», краткое: заведение, окно, код. CTA «Показать код» → C-12.

**C-12 Активный заказ (код/QR).** **Крупный код выдачи** + QR (компонент), кнопка «ярче». Заведение, адрес+«Открыть в 2GIS», окно выдачи, статус-бейдж, что внутри. Подсказка «покажите код на кассе». До конца окна — пуш-напоминание (BP-07). Статусы: `paid`→ после выдачи `picked_up` (экран превращается в «Выдан» + CTA «Оценить» → C-15).

**C-13 Заказы.** Табы **Активные / История**. Активные — карточки с кодом (→C-12). История — строки с бейджем статуса (`picked_up`/`expired`/`refunded`) (→C-14). Empty для обоих.

**C-14 Детали заказа.** Сводка прошлого заказа: заведение, дата, суммы (цена/сбор), статус. Если `picked_up` без оценки — CTA «Оценить». Если проблема — «Пожаловаться» (→C-16, доступно ограниченное время).

**C-15 Оценка.** Звёзды (1–5), опц. текст, опц. фото. «Отправить» → тост. Возможна развилка на жалобу при низкой оценке (→C-16).

**C-16 Жалоба.** Причина (чипы: просрочка/качество/несоответствие/другое), **обязательное фото** (загрузчик), описание. Дисклеймер «возврат рассматривает поддержка» (R4). «Отправить» → `Complaint open`, тост «жалоба принята». Валидация: без фото нельзя.

**C-17 Профиль/настройки.** Имя/телефон, язык RU/KK, уведомления, оферта/политика, «Спасено еды» (плейсхолдер v2), выход.

**C-E Системные состояния.** Набор: нет сети, серверная ошибка с ретраем, скелетоны главной и карточки, пустые состояния (нет боксов/нет заказов/нет истории).

### B. Приложение заведения

**M-01 Вход.** Телефон+OTP (как C-03/04). После входа — роутинг по роли.

**M-02 Регистрация заведения.** Многошаговая форма: название, категория, адрес+точка на карте, часы, **фото**, описание; юр.данные (ИП/ТОО, БИН/ИИН), **счёт для сплита (IBAN)**, согласие с агентским договором (ссылка). Прогресс по шагам, валидация. → сабмит → M-03.

**M-03 «На модерации».** Статус-экран (`pending_review`): «заявка на проверке», что дальше, контакт поддержки. После одобрения → M-04.

**M-04 Дашборд owner (сегодня).** Шапка: имя заведения, рейтинг, статус. **Крупная кнопка «Повторить вчерашний бокс»** (главный паттерн) + «Создать бокс». Блок «Сегодня»: активные боксы, продано/осталось, ближайшее окно. Быстрые цифры (продано боксов, выручка). Нижняя навигация: Дашборд · Боксы · Заказы · Статистика · Профиль.

**M-05 Создать бокс.** Поля: категория, цена, **ценность** (для расчёта скидки), количество, окно выдачи (с–до), фото (можно дефолт заведения). Подсказка-валидация правила «цена ≤ ⅓ ценности» ([06](docs/06-merchant-rules.md)). Превью карточки как увидит покупатель. «Опубликовать» → `published`.

**M-06 Повторить/Шаблоны.** Список вчерашних/сохранённых боксов → 1 тап «повторить» (подставляет всё, можно поправить окно/кол-во) → публикация. Управление шаблонами.

**M-07 Расписание.** Дни недели + время автопубликации бокса/шаблона. Вкл/выкл. (v1 базово / v2 расширенно.)

**M-08 Боксы (управление).** Список боксов со статусом (`published`/`sold_out`/`closed`/`scheduled`). На каждом: остаток (можно изменить, но не ниже проданного — BP-11), вкл/выкл, снять. **Снятие бокса с активными заказами** → модалка-предупреждение «покупателям вернутся деньги» (BP-11).

**M-09 Лента заказов.** Входящие брони в реальном времени (`paid`): время окна, кол-во, код (для сверки). Фильтр по окну/дате. Тап → детали заказа.

**M-10 Статистика.** Стат-карточки: продано боксов, выручка, **к выплате/выплачено**, рейтинг, sell-through. Период (день/неделя/месяц). Простые графики.

**M-11 Профиль заведения.** Редактирование данных из M-02 (фото, адрес, часы, описание). Юр.данные/счёт — только просмотр или через поддержку.

**M-12 Staff — заказы на сегодня.** Минимальный экран: список заказов по окнам выдачи (`paid`), крупно и просто. Без денег/настроек/статистики. Кнопка **«Принять выдачу»** (→M-13). Поиск по коду.

**M-13 Staff — ввод кода / скан QR.** Большое поле ввода кода ИЛИ камера-сканер QR. Проверка: код валиден, `paid`, окно активно, бокс этого заведения. → M-14.

**M-14 Staff — результат выдачи.** **Успех**: крупная галочка, «Выдано», что отдать (кол-во/категория) → `picked_up`. **Ошибки**: «неверный код», «уже выдан», «окно ещё не открылось» / «окно прошло (просрочен)». Кнопка «Отметить не пришёл» по истечении окна (BP-07).

### C. Админ-веб (W) — зеркало owner

Те же сущности и действия, что M-04…M-11, в десктоп-раскладке: левое/верхнее меню, контент по центру, таблицы вместо мобильных списков. Авторизация телефон+OTP. Адаптив 1440→768. Приоритет — после мобильного приложения (для сетей/тех, кому удобнее с ПК). Отдельные макеты: Дашборд, Боксы (таблица + «создать/повторить»), Заказы (таблица), Статистика, Профиль.

### D. Суперадмин

**S-01 Логин.** Вход основателя (телефон+OTP или email — уточнить). Безопасный, минималистичный.

**S-02 Дашборд метрик.** Стат-карточки: **GMV**, боксов продано, **доход (комиссия+сбор)**, эквайринг, активные заведения, активные покупатели, retention, sell-through, жалоб/100 заказов, % возвратов, **«спасено еды»**. Графики по времени. Фильтр период/город. (BP-14.)

**S-03 Заведения — список + модерация.** Таблица заведений (имя, статус, рейтинг, ставки, страйки). **Очередь модерации** (`pending_review`) с действиями одобрить/отклонить. Поиск/фильтр по статусу. Строка → S-04.

**S-04 Карточка заведения.** Профиль+юр.данные. **Настройка ставок:** `commission_pct`, `service_fee_pct`, `min_fee_per_box` (применяются к новым заказам — BP-12). Управление статусом: `active`/`suspend`/`deboard`. **Страйки** (журнал инцидентов, счётчик 1/2/3 — BP-10). История боксов/заказов заведения.

**S-05 Жалобы — список.** Таблица `open` жалоб: заказ, заведение, причина, дата, превью фото. Фильтр по статусу/заведению. Строка → S-06.

**S-06 Жалоба — детали.** **Фото крупно**, описание, вся история заказа (суммы, статусы), рейтинг/история заведения. Действия: **«Одобрить возврат»** (→ `refunded`, +страйк заведению, модалка подтверждения) или **«Отклонить»**. Примечание о сплит-откате (BP-09). Результат шлёт пуш покупателю.

**S-07 Заказы и транзакции.** Таблица всех заказов: поиск по коду/телефону/заведению, фильтр по статусу, суммы, метод оплаты, сплит. Детали транзакции, ручные корректировки.

**S-08 Выплаты / сверка.** Режим `split` — сверка автозачислений; режим `manual` (ранний пилот) — отчёт «к выплате заведению» + отметка о выплате/акте (BP-13).

**S-09 Пользователи.** Покупатели и сотрудники заведений; блокировки; базовый профиль/история.

## 7. Требования к прототипу (кликабельные сценарии)

Прототип должен проигрывать сквозные флоу (не только статичные экраны):

**Клиент (обязательно):**
1. Онбординг → телефон → OTP → разрешения → Главная.
2. **Главная → карточка бокса → бронь(итог с 3%) → оплата → успех → код выдачи** (ядро, demo happy path).
3. Активный заказ → (имитация выдачи) → оценка → жалоба с фото.
4. Пустое состояние «нет боксов рядом».

**Заведение (обязательно):**
5. Вход owner → дашборд → **«Повторить вчерашний» → публикация**.
6. Создание бокса с нуля (с превью карточки).
7. Вход staff → заказы сегодня → **ввод кода → успех выдачи**; и ветка ошибки «неверный код».

**Суперадмин (обязательно):**
8. Дашборд → Заведения → одобрить заявку из модерации → задать ставки.
9. Жалобы → открыть жалобу → одобрить возврат (с модалкой).

Для каждого ключевого экрана — варианты состояний (loading/empty/error) как отдельные фреймы, переключаемые в прототипе.

## 8. Доступность и адаптив

- Контраст ≥ 4.5:1 (текст), ≥ 3:1 (крупный/иконки). Проверить акцентный цвет особо.
- Тач-таргеты ≥ 44px; фокус-стейты для веба (клавиатура).
- Поддержка увеличенного системного шрифта (Dynamic Type) — не ломать раскладку.
- Локализация RU/KK: тексты длиннее — гибкие контейнеры, без обрезки; числа/даты/валюта по локали (`1 030 ₸`).
- Тёмная тема — **не в v1** (заложить токены, но макеты светлые).
