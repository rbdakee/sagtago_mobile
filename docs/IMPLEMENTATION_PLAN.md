# IMPLEMENTATION PLAN — SaqtaGo Mobile (клиент)

> Поэтапный план сборки клиентского приложения. Каждая фаза = осязаемый результат +
> критерий приёмки. Источники: [ARCHITECTURE.md](ARCHITECTURE.md), [BP.md](BP.md),
> [DESIGN.md](DESIGN.md), хендофф `mobile_design/sg/project/`.

## Принцип последовательности
Бэкенд — отдельный проект, **API пока нет**. Поэтому строим снизу вверх то, что от API не
зависит (фундамент → дизайн-система → статичные экраны), а интеграцию данных держим за
слоем репозиториев и подключаем, когда придёт контракт. Это не простой — ~60–70% работы
делается до API.

Легенда: 🟢 не зависит от API · 🔴 гейт на готовый API бэкенда.

## Phase 0 — Фундамент 🟢
**Цель:** запускающийся каркас на dev build.

- [ ] Инициализация Expo + TypeScript, `expo-router`, базовый `app/_layout.tsx` с провайдерами.
- [ ] EAS dev build (iOS/Android), профили сборки; ESLint + Prettier + strict TS.
- [ ] Шрифты Unbounded + Onest (`@expo-google-fonts`), загрузка до рендера.
- [ ] Порт токенов: `tokens.ts` + темы `graphite` / `graphite-dark`, `ThemeProvider`, `useTheme`.
- [ ] `prefsStore` (тема: system/light/dark + язык) с персистом; `useColorScheme` интеграция.
- [ ] i18n каркас (i18next + expo-localization), `ru.json` (+ пустой `kk.json`).
- [ ] Структура папок из ARCHITECTURE §3.

**Приёмка:** приложение стартует на устройстве, переключение темы и языка работает на тестовом экране, шрифты подхватываются.

## Phase 1 — Дизайн-система / UI-kit 🟢
**Цель:** все переиспользуемые компоненты из `components.css` + `UI Kit.html`, в обеих темах.

- [ ] Примитивы: Button (primary/dark/secondary/ghost/danger; L/M/S; full; loading/disabled),
      Input (+префикс +7, валидация), OTPInput (таймер ресенда), Chip, Badge (словарь статусов §4.1),
      Discount-тег, RatingStars (показ+ввод), Stepper, Toast, Divider, ListCard.
- [ ] Доменные: **BoxCard** (доступен/sold_out/скоро закроется), MerchantHeader, OrderRow,
      **CodeCard/QRCard**, Marker (для будущей карты), StatCard, TrustBlock.
- [ ] Glass: GlassTabBar, GlassNavBar, GlassBottomSheet, GlassFab (expo-blur, tint по теме).
- [ ] States: Loading-скелетоны, Empty, ErrorState (с ретраем).
- [ ] Внутренний экран-галерея для визуальной сверки со скриншотами хендоффа.

**Приёмка:** галерея совпадает с `UI Kit.html`/скриншотами в светлой и тёмной теме; компоненты используют только токены.

## Phase 2 — Статичные экраны и навигация 🟢
**Цель:** все экраны C-01…C-17 на плейсхолдер-данных + проигрываемые флоу из DESIGN.md §7.

- [ ] Онбординг-флоу: Splash → Онбординг → Телефон → OTP → Разрешения → Главная (UI, без реальной отправки OTP).
- [ ] Главная (список) + чипы-фильтры + bottom-sheet фильтров; экран «карта» — заглушка.
- [ ] Ядро покупки: Карточка бокса → Бронь (расчёт сбора 3% вживую) → Оплата (stub) → Успех → Активный заказ (код/QR).
- [ ] Заказы (Активные/История) → Детали → Оценка → Жалоба (+ обязательное фото) → тосты.
- [ ] Избранное, Профиль (язык RU/KK + переключатель темы).
- [ ] Для Главной/Заказов/Карточки — переключаемые Loading/Empty/Error фреймы.

**Приёмка:** кликабельные сквозные сценарии §7 проигрываются на устройстве; pixel-совпадение с `Prototype.html` в обеих темах; все строки — через i18n.

## Phase 3 — Доменная модель и слой данных 🟢→🔴
**Цель:** типы/правила сейчас; подключение реального API — по готовности бэкенда.

- [ ] 🟢 `domain/`: типы, enum-статусы, zod-схемы, `rules.ts` (сбор 3%, скидка, проверка окна) + тесты.
- [ ] 🟢 Интерфейсы репозиториев + реализация на плейсхолдерах; TanStack Query-хуки поверх них.
- [ ] 🟢 Перевод экранов Phase 2 с инлайн-данных на Query-хуки (источник — плейсхолдер-репозитории).
- [ ] 🔴 `data/api/`: http-клиент + реализации репозиториев по контракту; подмена фабрики репозиториев.
- [ ] 🔴 Реальный auth: отправка/проверка OTP, токены в secure-store, guard маршрутов, рефреш сессии.

**Приёмка:** экраны работают через Query (loading/empty/error реальны); при появлении API подмена транспорта не требует правок экранов.

---

## Phase 4 — Платёж (Freedom Pay) 🔴
**Цель:** реальная оплата по агентской схеме (со стороны клиента).

- [ ] Создание заказа → платёжная сессия (бэкенд) → открытие страницы/виджета провайдера.
- [ ] Ожидание статуса `paid` (refetch/пуш) → Успех + код; обработка `payment_failed`, таймаута hold.
- [ ] Методы: Kaspi / карта / Apple·Google Pay (по факту провайдера).

**Приёмка:** happy-path оплаты и ветка отказа проходят на sandbox провайдера.

## Отложено (вне MVP-плана)
- Экран карты с реальным SDK (2GIS/Mapbox) — выбор и интеграция, когда дойдём до карты.
- Приложение заведения/staff (M-экраны) — отдельный проект.
- Антифрод, расписание боксов, «спасено еды» геймификация — v2+.

## Гейты, ожидающие бэкенд (свести к контракту заранее)
1. Auth: отправка/верификация OTP, формат сессии/токена.
2. Каталог: список/деталь боксов, фильтры, гео.
3. Заказы: создание (бронь), статусы, активные/история, код выдачи/QR.
4. Платёж: создание сессии Freedom Pay, источник статуса для клиента.
5. Жалоба/оценка: создание, загрузка фото; избранное.
6. Пуши: регистрация токена устройства, типы уведомлений.
